# Dependency remediation — 11 September 2026

The reviewed lockfile had seven vulnerable package entries covering six advisories. Compatible transitive updates and removal of unused `fflate` reduced that to the two entries for Vitest's single advisory. Vitest was then upgraded from 3.2.7 to the first fixed stable version, **4.1.11**, pinned exactly in `package.json`. Full and production-only `npm audit` now report **zero advisories**.

## Changes and reachability

| Dependency chain | Change | Advisory and assessed exposure |
| --- | --- | --- |
| Root → `fflate` | Removed unused 0.8.2 | [Malformed ZIP64 can hang `unzipSync`](https://github.com/advisories/GHSA-px8p-9vwx-vf98). Repository searches found no imports or ZIP APIs in application code, tools, public assets or documentation. There is no implemented ZIP import flow. Current project import uses JSON or Git files; binary transport does not use this library. |
| ESLint → `@humanfs/node` | 0.16.6 → 0.16.8 | [Recursive copy follows symlinks outside its source](https://github.com/advisories/GHSA-p498-v437-472g). Development tooling only. The installed ESLint call sites use directory checks and walking, not the affected copy API. |
| Schema ref parser / ESLint config → `js-yaml` | 4.3.1 → 4.3.2 | [Empty YAML merge sources bypass CPU limits](https://github.com/advisories/GHSA-2883-xcg3-v3hh). Development schema generation and ESLint configuration; application YAML parsing uses the separate `yaml` package. |
| Vite / Vue SFC compiler → PostCSS → `nanoid` | 3.3.17 → 3.3.19 | [Zero-sized custom generators may loop](https://github.com/advisories/GHSA-2v37-7h3g-55p8). Present in the production dependency graph through Vue's compiler, as well as build tooling. The inspected PostCSS caller uses `nanoid(6)`, not a custom generator or an attacker-controlled size. No application imports were found. |
| ESLint Vue plugin → `postcss-selector-parser` | 6.1.2 → 6.1.4 | [Unbounded AST serialization recursion](https://github.com/advisories/GHSA-w9m9-85wc-3x92). Development linting only. |
| Vitest → `@vitest/mocker` | Both 3.2.7 → 4.1.11 | [Redirect mocks may read outside Vite's allowlist](https://github.com/vitest-dev/vitest/security/advisories/GHSA-82fw-gwwq-j7x9). Test tooling only; this project uses jsdom tests and does not install the public mocker plugin into its application dev server. The advisory confirms that Vitest 3 is unmaintained and will not receive the fix. |

These are call-site assessments, not a claim that every transitive package is unreachable. In particular, npm's production graph includes compiler/build dependencies and is not identical to the browser bundle.

The [Vitest 4 migration requirements](https://v4.vitest.dev/guide/migration) are compatible with the project's existing Node and Vite ranges. No Vue, router, Vite or editor library major upgrade was required. The lockfile changes include Vitest's required dependency graph, its newer `magic-string` requirement and shared source-map codec, and the patched humanfs dependency graph. No overrides, forced audit upgrade, package-wide update or audit suppression was used.

## Validation

- Clean, isolated `npm ci` using Node 24.21.0; committed lockfile remained unchanged by installation.
- All **131 test files / 1,134 tests passed** under Vitest 4.1.11.
- ESLint passed without warnings. Scoped strict TypeScript checks passed for project files, providers, repository adapter, Git synchronization and reopening services.
- Production build passed. The existing lazy ConfigTab chunk remains approximately 661 kB and still produces Vite's size advisory.
- Production Chromium on ordinary HTTP, at 1440 px and 390 px, passed: read-only Git preview; pinned reopening; restored forms; byte-exact binary download after reload; preservation of earlier local drafts; files-only import preserving manually changed generated bytes on Save; actual dashboard JSON-file import with exact binary download after reload. Modal axe scan found no violations; no page errors or horizontal overflow were observed. Git and backend responses were isolated browser fixtures; no PVE changes or live repository writes were made in this dependency wave.
- Independent review found the semantic lock changes confined to the selected fixes and required Vitest dependencies.
- Audit and browser summaries are retained under `docs/acceptance/dependencies-20260911-*.json`.

The first run exposed test harness assumptions rather than product regressions. Three storage-quota tests now replace the jsdom Storage proxy through `vi.stubGlobal` and restore it in `finally`, so they actually exercise failed persistence. Two catalog fixtures wait for the expected rendered entry count instead of assuming one promise-flush turn completes dynamic imports. Assertions were preserved; no tests were skipped.

ZIP archive import is still not implemented. Existing binary asset limits remain 1 MiB per file and 2 MiB per project file snapshot; this dependency update does not enlarge browser storage capacity. The zero-advisory result records the registry audit on this date and does not replace application-level review.
